Principle
A useful postmortem changes the system

        
The weakest postmortem is a long description of something that already happened. A useful one ends with a few testable changes: a guardrail, automation, alert, smaller blast radius, restore test, or process change.
If nothing changes after the document, the next similar incident will simply be documented better.
