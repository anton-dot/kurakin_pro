Local-firstOwnership

Local-first writing software: keep the project as a file you control.

Long-term writing deserves a storage model that does not begin with “your manuscript lives on our server.” B-Maker stores the writing project as a portable .bmaker file.

What local-first means here

Your book or article collection can remain a file under your control. Keep it on your computer, include it in your own backup routine, move it between machines, or place it in a cloud drive you already use. B-Maker does not require a proprietary cloud account to make the manuscript exist.

The manuscript should survive the service

A book may take years. An article archive may outlive several laptops, applications, and subscriptions. For that kind of work, portability matters. The canonical project should be something the writer can copy, archive, back up, and move without asking a server for permission.

One file, more than plain text

The .bmaker project is not just the current manuscript. It keeps the structure, current and earlier versions, comments, collections, planning entities, idea-map data, cover and illustrations, analytics metadata, and publishing information together.

That is useful because “local-first” does not have to mean “a folder full of disconnected files.” The project can still be structured while remaining portable.

Use the backup system you already trust

Because the project is a file, it can fit into ordinary backup strategies: local copies, external storage, NAS, versioned cloud drives, or any combination you prefer. B-Maker also provides manual backup history and integrity checks inside the application.

What about the web version?

B-Maker also runs in a browser. The browser workspace can be downloaded as a portable .bmaker project when needed. Browser file behavior varies by platform and browser, so the native Windows application remains the most direct local-file workflow today, while Mac, Linux and Chromebook users can use the web version.

What local-first does not mean

It does not mean collaboration and sync are impossible forever. It means the local project remains the foundation. Future synchronization or sharing features can be added without turning the remote service into the only copy of the manuscript.

Who benefits most

Local-first is particularly attractive to authors working on long-lived projects, writers handling unpublished material, people who already have a trusted backup workflow, and anyone who wants to reduce dependence on one vendor's cloud.

One project. One file. Yours.

That is not just a tagline; it is the storage model B-Maker is designed around.
