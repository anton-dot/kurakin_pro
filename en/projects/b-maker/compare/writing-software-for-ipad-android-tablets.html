iPadAndroid tablets

Writing on a tablet without moving the project into someone else’s cloud.

B-Maker has no native iPad or Android app today. The web version runs in a modern browser, so the same project model can still be used on tablets when you want a larger screen away from the desktop.

What the tablet workflow is today

Open B-Maker in the browser, work with the manuscript and planning tools, then download the project as a portable .bmaker file when you need an external copy. There is no promise of invisible background sync between devices.

Why a tablet can be useful for long-form writing

An iPad or Android tablet sits between a phone and a laptop: large enough for reading a chapter, reviewing a board, or editing with a hardware keyboard, but easier to carry. For some writers it becomes a secondary device for review and focused drafting rather than the only workstation.

The project is still more than a document

The browser version keeps the same core model: books and articles, manuscript structure, collections, Idea Map, characters and plotlines, versions, analytics, and publishing preparation. You are not reduced to a stripped-down note editor simply because you opened the project on a tablet.

What is different from a native tablet app

Browser file handling differs between operating systems and browsers, especially on iPadOS. B-Maker therefore does not describe tablet use as seamless file synchronization. If your workflow depends on automatic cross-device sync, native file integration, or deep OS shortcuts, a dedicated native app may fit better today.

A practical mixed-device workflow

Use Windows as the native desktop environment when available, use the browser on iPad or Android for review and editing, and keep portable project copies using the storage method you already trust. The important part is that the manuscript remains exportable as a project file instead of existing only inside an account.

Good fit if…

You want to open a serious writing project on a tablet without requiring a separate mobile database or proprietary cloud account, and you are comfortable with a browser-based workflow rather than expecting native iPadOS or Android integration.
