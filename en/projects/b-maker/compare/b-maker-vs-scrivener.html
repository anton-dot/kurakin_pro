B-Maker vs Scrivener

Scrivener is the mature power tool. B-Maker is trying to make the common book workflow smaller, faster to enter, and easier to carry as one local-first project.

Short answer

Choose Scrivener if you want a proven, extremely deep long-form writing environment and are willing to learn it. Try B-Maker if your priority is opening a project and writing immediately, while keeping planning, versions, book data, and publishing output in one portable project.

The biggest difference is philosophy

Scrivener has had years to grow into a broad professional environment. Its strength is depth: the Binder, Corkboard, Outliner, metadata, research storage, Snapshots, flexible Compile system, and many other tools can support very complex manuscripts.

B-Maker is deliberately moving in the opposite direction on one axis: it tries to expose the simplest path first. Create a project, add a chapter, write. Characters, plotlines, versions, text checks, illustrations, and export exist around that writing flow rather than being prerequisites for it.

Project ownership and sync

B-Maker currently has no mandatory account or cloud backend. A book is stored as a portable .bmaker project file. That is useful if you prefer local storage and your own backup or cloud-drive workflow, but it also means there is no built-in cross-device synchronization or real-time collaboration today.

Scrivener is also fundamentally desktop-file oriented, but its iOS workflow supports Dropbox synchronization. Literature & Latte sells macOS, Windows, and iOS versions, with platform licensing handled separately.

Revisions

Both products recognize that writers need to rewrite without destroying previous work. Scrivener provides Snapshots and comparison tools. B-Maker stores multiple versions of chapters or scenes inside the project. The product goal is similar; the interfaces and surrounding workflow differ.

Export and publishing

Scrivener's Compile system is considerably more mature and configurable. That flexibility is valuable if you need detailed output control. B-Maker aims for a more opinionated publishing flow: preview the book, add cover and illustrations, and export to common formats without exposing as many controls at once.

Who should choose Scrivener?

  • You want a mature tool with years of development behind it.
  • You need deep outlining, metadata, research, and Compile options.
  • You work on macOS and want a native app now.
  • You already have a Scrivener workflow that works.

Who should try B-Maker?

  • You want to start writing before learning a large application.
  • You like the idea of one portable project containing more than the manuscript.
  • You prefer a local-first workflow without mandatory cloud storage.
  • You want writing, characters, plot information, versions, checks, illustrations, and export close together.

Verdict

Scrivener is currently the stronger choice if maximum depth and maturity matter most. B-Maker is interesting when the friction of a large writing system is itself the problem you want to remove. The goal is not to reproduce every Scrivener feature — it is to cover the book workflow with fewer concepts.
